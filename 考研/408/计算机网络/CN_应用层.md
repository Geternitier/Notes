## 6. 应用层



### 6.1 概述

应用层基于下层提供的通信能力，提供节点之间的应用服务。

网络应用模型主要有**C/S**模型和**P2P**模型。

C/S模型的特点：

1. Client请求服务，Server提供服务；
2. Client间通常不通信；
3. 主机地位不平等。

P2P模型的特点：

1. 每个节点都具有上传和下载的能力，地位平等；
2. 多节点间可以直接通信；
3. 可扩展性强，健壮性强。



### 6.2 DNS

**域名系统 DNS**用于建立域名和IP地址之间的映射。

域名可以区分为顶级域名TLD、二级域名、三级域名等，顶级域名分类如下：

1. 国家域名：例如.cn、.us
2. 通用域名：例如.com、.net、.org
3. 基础结构域名.arpa：用于IP地址反向解析域名

层次域名空间：标号.标号.标号

1. 标号英文不区分大小写；
2. 标号中标点符号只能使用连字符 - ；
3. 低级域名写在左侧；
4. 标号不超过63个字符，完整域名不超过255个字符。

**域名服务器**：

1. 根域名服务器：知道所有顶级域名服务器的域名和IP地址
2. 顶级域名服务器：管理所有在该顶级域名下的二级域名

3. 权限域名服务器：将管理的主机名转化为IP地址

4. 本地域名服务器：局域网DNS服务器

**域名解析**：**递归查询**、**迭代查询**，使用UDP。

1. 主机向本地域名服务器进行递归查询；
2. 本地域名服务器向其他域名服务器一般使用迭代查询。

域名查询使用**任播**技术。



### 6.3 FTP

**文件传输协议 FTP**提供交互式文件访问，允许指明文件的类型、格式和存取权限。

1. FTP服务器监听端口21，客户进程在此端口建立TCP连接传输控制信息；
2. 文件列表、文件数据通过建立TCP数据连接传输：
   1. 客户发送**PORT**命令和端口号，服务器收到后使用20端口连接客户，发送数据。
   2. 客户发送**PASV**命令，服务器发送随机端口号给客户，客户连接服务器接收数据。

这种控制和数据分离的数据传输方式称为**带外传送**。

FTP修改文件时，需要先下载再上传，效率较低。**网络文件系统 NFS**支持远程编辑文件。



### 6.4 E-mail

电子邮件结构：To+Subject+From+Body

电子邮件收发过程：

1. 用户通过**用户代理**，使用SMTP将邮件发送给**发送端邮件服务器**；
2. **发送端邮件服务器**使用SMTP将邮件发送到**接收端邮件服务器**；
3. **用户代理**使用POP3、IMAP等协议从**接收端邮件服务器**拉取邮件。

实际上，用户收发电子邮件往往使用HTTP为主，仅在邮件服务器间使用SMTP。

**简单邮件传输协议 SMTP**基于TCP协议，使用端口号25，使用C/S模型。

1. 建立TCP连接；
2. Server发送220 Service ready，Client发送HELO和主机名；
3. 发送邮件：
   1. Client发送MAIL和发件人地址，Server准备好则返回250 OK；
   2. Client发送一个或多个附带收件人地址的RCPT命令，Server回复收件人是否存在；
   3. 全部确认后，客户发送DATA，服务器返回354；
   4. 客户开始传输数据，用```<CRLF>.<CRLF>```结束；
   5. 客户发送QUIT，服务器返回221，释放连接。

**多用途互联网邮件扩展 MIME**：将其他二进制对象转化为SMTP能发送的7位ASCII码与解码。

**邮局协议 POP**：TCP，C/S，端口号110。服务方式包括**下载并删除**、**下载并保留**。

**互联网报文存取协议 IMAP**：支持邮件文件夹、搜索、允许用户选择性地获取邮件内容。



### 6.5 HTTP

#### WWW

World Wide Web是互联网资源的应用规范，通过**统一资源定位符 URL**定位任何互联网资源，使用**超文本传输协议 HTTP**进行通信，凭借**超文本标记语言 HTML**呈现信息，构成了互联网的主要部分。

URL的结构：```<协议>://<主机>:<端口>/<路径>```



#### HTTP

HTTP基于TCP，使用端口号80提供服务。

1. Client和Server建立TCP连接；
2. Client发送HTTP请求；
3. Server返回HTTP响应。

HTTP/1.0中，每次HTTP请求都需要建立新的TCP连接；HTTP/1.1中，默认复用TCP连接。

HTTP本身是**无状态**的，不会记录用户的历史信息。实际应用使用**Cookie**来跟踪用户行为：

1. 用户首次访问时，服务器为其生成Cookie识别码，在响应中设置「Set-cookie：xxx」；
2. 用户后续访问时，在请求中附加「Cookie：xxx」，服务端根据Cookie获取用户历史行为。

**HTTP请求结构**：

```
GET <Address> HTTP/1.1
Host: www.sina.com.cn
User-Agent: M/5.0 xxx
Accept: **/**
Accept-Language: zh-CN,zh;q=0.9,en-US;q=0.8
```

第一行使用GET请求获取路径为`<Address>`的资源，使用HTTP/1.1协议；

第二行开始，每行都是Header：Value的HTTP头，常用的HTTP头：

1. Host：表示请求的主机名，因为一个服务器上可能运行着多个网站，因此，Host表示浏览器正在请求的域名；
2. User-Agent：标识客户端本身，例如Chrome浏览器的标识类似M/5.0 ... Chrome/79；

3. Accept：表示浏览器能接收的资源类型，如`text/*`，`image/*`或者`*/*`表示所有；

4. Accept-Language：表示浏览器偏好的语言，服务器可以据此返回不同语言的网页；

5. Accept-Encoding：表示浏览器可以支持的压缩类型，例如gzip, deflate, br。

**HTTP响应结构**：

```
HTTP/1.1 200 OK
Content-Type: text/html
Content-Length: 21932
Content-Encoding: gzip
Cache-Control: max-age=300
```

第一行是版本、Code、文本。

Code中，2xx表示成功，3xx表示重定向，4xx表示客户端错误，5xx表示服务端错误。

1. 200 OK：表示成功；
2. 301 Moved Permanently：表示该URL已经永久重定向；
3. 302 Found：表示该URL需要临时重定向；
4. 304 Not Modified：表示该资源没有修改，客户端可以使用本地缓存的版本；
5. 400 Bad Request：表示客户端发送了一个错误的请求，例如参数无效；
6. 401 Unauthorized：表示客户端因为身份未验证而不允许访问该URL；
7. 403 Forbidden：表示服务器因为权限问题拒绝了客户端的请求；
8. 404 Not Found：表示客户端请求了一个不存在的资源；
9. 405 Method Not Allowed
10. 500 Internal Server Error：表示服务器处理时内部出错，例如因为无法连接数据库；
11. 503 Service Unavailable：表示服务器此刻暂时无法处理请求。

从第二行开始，服务器每一行均返回一个HTTP头，服务器常返回的HTTP头有：

1. Content-Type：表示该响应内容的类型，例如text/html，image/jpeg；
2. Content-Length：表示该响应内容的长度（字节数）；
3. Content-Encoding：表示该响应压缩算法，例如gzip；
4. Cache-Control：指示客户端应如何缓存，例如max-age=300表示可以最多缓存300秒。

HTTP请求和响应都由HTTP Header和Body组成，Header每行都以\r\n结束，如果有两个连续的\r\n，那么后面即是HTTP Body。浏览器读取HTTP Body，并根据Content-Type、Content-Encoding等解压后显示网页、图像等内容。
