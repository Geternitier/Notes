# 网络层

网络层提供主机到主机的通信服务，将报文（分组）从源主机经过多个网段、链路传输到目的主机。

网络层的核心协议是IP协议，基本数据单元为IP数据报。



## 网络协议 IP

Internet Protocol，自然是网络层协议

网络协议屏蔽物理网络之间差异，使网络中主机无需关注网络细节进行连接，形成虚拟网络。

具体来说，就是使用IP地址在互联网上唯一地标识和定位网络和设备，以便它们之间的通信。

核心技术：地址分配、数据报文、分组交换和路由选择。

- 在IP网络中通信，每个主机都需要拥有一个IP地址，用于标识主机在网络中的位置。
  - 主机只需一个IP地址就可以参与通信。
  - 网络设备作为中转站，每个接口都具有一个或多个IP地址，用于指导数据转发。
- IP地址并不是一种物理地址，而是逻辑地址，即地址是可以被分配、非固定、可修改的。

异构网络互联：将多个物理结构不定的计算机网络连接起来。



### IPv4

Internet Protocol version 4

#### IPv4地址

IPv4使用32位二进制数在互联网上标识设备，也就是说IPv4最多有约42亿个地址。

1. 点分表示：8位一组，每组用十进制或者十六进制表示。例如192.168.1.1。
   - 如果某个8位组为0，可以省略，如192.168..1。
2. 地址划分：前缀网络位标识所在网段的位置，后缀主机位则标识主机在网段中位置。
   - 主类网划分：早期设计，如今IP分配已经被广泛地调整和优化。
     - A类地址：8位网络位，24位主机位，位前缀为0，即0.0.0.0～127.255.255.255。
     - B类地址：16位网络位，16位主机位，位前缀为10，即128.0.0.0～191.255.255.255。
     - C类地址：24位网络位，8位主机位，位前缀为110，即192.0.0.0～223.255.255.255。
     - D类地址为组播（多播）地址，位前缀1110，即224.0.0.0～239.255.255.255。
       - 关于组播（多播），详见IGMP。
     - E类地址为保留地址，位前缀1111，即240.0.0.0～255.255.255.255。
   - IP数据报在网络中传递时，路由器只关心目的IP的网络位，到了目的网段后再查找主机。
3. 子网：将一个网段分成多个子网可以更有效的管理。IP地址划分为主网位、子网位和主机位。
   - 子网掩码：网络位全1，主机位全0，用来划分网络和主机部分，与IP地址共同构成网络地址。
     - 子网掩码和IP地址作与运算得到子网地址。
   - 默认网关：子网与外部网络连接的设备地址。
     - 进行报文转发时，如果目的地址不在子网中，则发送到默认网关。
4. 无分类域间路由，Classless Inter-Domain Routing，CIDR：
   - 无分类，即不具有主类网划分的ABC等类地址。
   - 记网络为”IP地址/子网位数“，如192.168.1.1/26。
   - 特定主机路由：子网位数32，用于特定目的，a.b.c.d/32。
5. 主机位全0和全1的地址不能分配。
   - 主机位全0的地址为默认路由，通常用于路由器到互联网。
   - 主机位全1的地址为广播地址。



#### IPv4数据报

IP数据报：首部+数据

首部固定长度共20B，后面字段可选，最多60B。

- 版本（4位）：4
- 首部长度（4位）：一般为5（$5\times32bit=20B$），最长60B。
- 服务类型（8位）：只有在有QoS差分服务要求时才有用。
- 总长度（16位）：包括首部和数据，单位为B，最长65535。
- 标识（16位）：计数器，每产生一个数据报加1，用于分片重组。
- 标志（3位）：分别为0、DF、MF。DF=0表示允许分片，MF=1表示后面还有分片。
- 片偏移（13位）：分片重组时，指出片在原数据报的相对位置，单位为8B
- 生存时间（8位）：可通过的路由器数最大值，路由器转发前减1，然后判断为0则丢弃
- 协议（8位）：下一层协议号。6为TCP，17为UDP。
- 首部检验和（16位）
- 源IP地址（32位）
- 目的IP地址（32位）
- 选项（可变，从1字节到40字节不等）：用于排错、安全等。
- 填充（可变）：全填0。



#### IPv4分组转发

1. 从IP分组的首部提取目的IP地址；
2. 若有特定主机路由，则按照该路由转发分组，否则下一步；
3. 计算子网，查找路由表，若查找到则进行转发，否则下一步；
   - 路由聚合：根据IP地址的公共前缀以二叉搜索树的方式构建路由表。
4. 如果有默认路由，则转发给默认路由，否则出错。



#### 地址解析协议 ARP

Address Resolution Protocol，涉及IP，是网络层协议

查表得到下一个路由器的IP地址后，需要先将其转换为MAC地址，再进行数据链路层传输。

ARP是将IP地址解析为MAC地址的协议，主机或网络层设备会维护一张ARP表，用于存储IP地址和MAC地址的映射关系。ARP表项可以分为动态ARP、静态ARP。

1. 动态ARP：通过ARP报文自动生成和维护，可以被老化，可以被新的ARP报文更新，也可以被静态ARP表项覆盖。适用于拓扑结构复杂、通信实时性要求高的网络。
   - 当网络中存在ARP攻击时，设备中动态ARP表项可能会被更新成错误的ARP表项，或者被老化，造成合法用户通信异常。
2. 静态ARP：由网络管理员手工建立的IP地址和MAC地址之间固定的映射关系。静态ARP表项不会被老化，不会被动态ARP表项覆盖。
   - 短静态：不指定VLAN和出接口，仍需发送ARP请求，获取IP、MAC映射对应的VLAN的出接口。
   - 长静态：指定VLAN和出接口，可以直接用于报文转发。



##### 地址解析过程

1. 发送数据报时，查ARP表，若有对应MAC地址，则将数据报写入MAC帧进行传输，否则下一步。
2. 缓存数据报，广播ARP请求，**目的主机**以单播的方式返回IP和MAC的映射信息。
3. 更新ARP表，将数据报写入MAC帧进行传输。



##### 技术细节

ARP老化：每台主机都维护一个ARP高速缓存，记录最近学习到的动态ARP表项。

- 对高速缓存中的动态ARP表项设置老化超时时间、老化探测次数和老化探测模式。
- 到达老化超时时间后，发送ARP请求报文，收到则更新，这是一次老化探测。
- 如果超过老化探测次数后没有收到应答，就删除该表项。
- 老化探测模式决定ARP请求报文是以单播还是广播发送，默认最后一次广播，其余都是单播。

免费ARP：使用自己的IP地址作为目的IP发送ARP请求。

- 冲突检测：发送该报文，并收到回复说明本网络中存在与自身IP重复的地址。
  - 检测到冲突后，周期性地发送免费ARP报文直到冲突消除。
- 通告新的MAC地址：发送方更换网卡使得MAC地址老化，发送免费ARP以更新。

代理ARP：具备代理ARP功能的网关可以代理回答同一网段、不同物理网络的主机的ARP请求。



#### IPv4分片重组

当IPv4报文的长度大于数据链路层最大传输单元（Maximum Transmission Unit，MTU）时，需要对报文进行分片，以使他们可以在网络上传输。

- 报文长度大于MTU且不允许分片，那么路由器会返回ICMP报文，Type 3（Destination Unreachable），Code 4（Fragmentation Needed but DF set），包含MTU信息。

分片：由发送方主机或者中间路由器完成。

1. 发送端根据目标主机的MTU，检查将要发送的报文大小。
2. 如果报文长度超过了MTU，发送端就会将数据包分割成更小的片段，每个片段大小不能超过MTU。
3. 每个片段都是一个独立的IP报文，但它们共享相同的IP头部信息（除了片偏移和分片标志段不同）。

重组：由目的主机完成。

1. 接收端收到这些分片后，根据每个IP数据包的标识符、片偏移和分片标志来确定它们应该如何组装。
2. 接收端将所有分片组合成原始IP报文。
3. 重组后的完整报文被传递给上层协议处理。



#### 动态主机配置协议 DHCP

Dynamic Host Configuration Protocol，基于UDP，使用C/S架构，是应用层协议。

准确、自动地为每个连接网络的设备分配IP地址。

既可以动态分配IP，也可以让网络管理员通过DHCP进行静态分配IP，避免直接人工配置发生错误。

- 客户端使用源端口号68，目的端口号67的UDP报文
- 服务器使用源端口号67，目的端口号68的UDP报文
- 当客户端和服务器不在同一个网段时，必须部署DHCP中继来转发报文。

无中继DHCP工作流程

1. 发现阶段：客户端广播DISCOVER报文，源地址0.0.0.0，携带客户端MAC地址与期望租期。
   - 服务器的地址池中会指定IP地址的租期。
2. 提供阶段：服务器广播OFFER报文，源地址为服务器地址，携带可用IP地址。
   - 服务器会比较租期，选择符合期望租期的时间较短者。
3. 选择阶段：客户端广播REQUEST报文，包含服务器标识符和客户端IP地址。
   - 可能有多个服务器回应OFFER报文，客户端一般接受第一个。
4. 确认阶段：服务器广播ACK报文。
   - 客户端收到ACK报文后，会广播免费ARP报文，如果收到回应，会向服务器发送DECLINE并重新请求IP地址。服务器会将此地址列为冲突地址，在没有空闲地址可分配时再选择。
   - 如果由于协商出错，此IP已被分配给其他客户端，会发送NAK报文，客户端收到后重新开始发现。

有中继DHCP中，对客户端来说，DHCP中继是服务端；对服务端而言，DHCP中继是客户端。

- 客户端和中继的交互流程和无中继DHCP一样。
- DHCP中继和DHCP服务器以单播的方式发送报文，其余和无中继DHCP一样。



#### 网络地址转换 NAT

Network Address Translation，In fact，Network Address Port Translation，NAPT

随着网络应用的增多，IPv4地址枯竭的问题越来越严重。在IPv6广泛应用之前，使用一些过渡技术（如CIDR、私网地址等）是解决这个问题的主要方式，NAT就是这众多过渡技术中的一种。

当私网用户访问公网的报文到达具有NAT功能的网关设备后，网关设备会将IP数据报文头中的IP地址转换为另一个IP地址，端口号转换为另一个端口号，再转发给公网。

- 早期的NAT仅仅支持地址转换，只解决私网主机访问公网的问题，不能解决IPv4地址枯竭的问题，后期的NAT实际上说的是NAPT，既转换地址也转换端口，多台私网主机共享一个公网IP，改善IP地址短缺。
- 端口地址转换，Port Address Translation，PAT，指一个IP使用多个端口从而实现多个设备共享同一IP，现在使用时和NAPT是一个概念。
- NAT设备维护记录转换前后的IP+端口的NAT表用于转换。

根据实际转换的地址，NAT可以分为源NAT、目的NAT和双向NAT。

1. 源NAT，SNAT：仅对源地址进行转换，用于私网访问公网。
   - NAT No-PAT：一对一转换私网地址到公网地址。
   - NAPT（PAT）：使用一个公网地址池，实现多个私网地址到一个或多个公网地址的转换。
   - Easy IP：使用出接口的公网IP地址作为NAT转换后的地址。
2. 目的NAT，DNAT：仅对目的地址和目的端口进行转换，用于公网访问私网。
   - 静态DNAT：转换前后地址存在固定映射关系。
   - 动态DNAT：转换前后地址不存在固定映射。
   - NAT Server：特殊的静态DNAT，使用Server进行报文的公网地址转换。
3. 双向NAT：组合SNAT和DNAT，用于同时有公网访问私网和私网访问外网的场景。



#### 网络控制报文协议 ICMP

Internet Control Message Protocol，是网络层协议。

ICMP是一个差错报告机制，当数据报处理出现差错，ICMP向数据报的源设备报告错误。

ICMP实际上封装在IP数据报内部，作为IP数据报的数据部分。因此它既不会纠正差错，也不会通知中间网络设备。

- ICMP头：Type（8位）、Code（8位）、检验和（16位）

##### PING

Ping程序是最常见的用于检测IPv4和IPv6网络设备是否可达的调试手段，它使用ICMP的echo信息来确定：

- 远程设备是否可达；
- 与远程主机通信的来回旅程（round-trip）的延迟；
- 报文包的丢失情况。



##### ICMP安全

ICMP本身的简单和无验证使得它非常容易成为攻击交互机、路由器等网络设备的武器。

大部分ICMP攻击都可以归类为拒绝服务攻击（Denial of Service，DOS），其中最为常见的是ICMP泛洪攻击，是指攻击者在短时间内向目标设备发送大量的ICMP虚假报文，导致目标设备忙于应付无用报文，而无法为用户提供正常服务。

DOS攻击可以分为针对带宽（大量Echo）、针对连接（对特定端口发送目的不可达）、针对主机（攻击操作系统漏洞）。

防范ICMP攻击的方法主要有报文限速（端口、VLAN和全局）、合法性检测与丢弃、不响应不可达报文。



#### 网络组管理协议 IGMP

Internet Group Management Protocol，是网络层协议，报文封装在IP报文中。

IGMP是在主机和与其所在网段直接相邻的组播路由器之间建立、维护组播的组成员关系的协议。

IGMP具有三个版本，向后兼容：

- IGMPv1定义了组成员查询和报告过程。
- IGMPv2添加了查询器选举和组成员离开的机制。
- IGMPv3添加了成员可以指定接收或者不接收某些组播源的报文。



IGMP使用**协议无关组播**进行报文转发。

协议无关组播，Protocol Independent Multicast，PIM

协议无关指与单播路由协议无关。

PIM利用单播路由表的路由信息，对组播报文执行逆向路径转发（Reverse Path Forwarding，RPF）检查，检查通过后创建组播路由表项，从而转发组播报文。



##### IGMPv1

当一个网段内有多个组播路由器时，由于它们都可以接收到主机发送的成员报告报文，因此只需要选取其中一台组播路由器发送查询报文就足够了，该组播路由器称为IGMP查询器。

IGMPv1的工作机制可以分为普遍组查询和响应、新组成员加入和组成员离开三个方面。

1. 普遍组查询和响应：查询器对网段内的组播组及其成员建立认识。
   - 查询器使用缺省为60s的周期向224.0.0.1发送普遍组查询报文。
   - 组播组的成员接收到查询报文后，启动定时器，缺省为0～10s内的随机值。第一个超时的组成员发送该组的报告报文，其他组成员的报文被抑制，不再发送。
   - 查询器接收到报告报文，根据组播路由协议生成组播转发表。
2. 新成员加入：
   - 主机主动发送针对某个组的报告报文声明加入。
   - 查询器接收到报告报文后，如果该组为新增，就生成对应组播转发项。
3. 组成员离开：主机离开组后，就不会响应普遍组查询报文。
   - 如果某个组的成员都离开，查询器接收不到该组的报告报文，就在缺省为130s的时间后，删除该组的转发表项。



##### IGMPv2

1. 查询器选举：
   - 最初，所有IGMPv2路由器都认为自己是查询器，发送普遍组查询报文。
   - 两个路由器相互收到普遍组查询报文后，IP地址大的路由器认为自己为非查询器。
   - 非查询器上启动一个定时器，如果超时前收到查询报文，就重置定时器，否则再次认为自己为查询器。
2. 组成员离开：
   - 主机向224.0.0.2发送针对某个组的离开报文。
   - 查询器收到离开报文后，发送针对该组的特定组查询报文，缺省每1s发送一次，共2次。同时查询器启动组成员关系定时器。
   - 该组的其他成员收到特定组查询报文后立即发送该组的报告报文。
   - 查询器在定时器超时之前收到报告报文，则继续维护该组成员关系。否则删除转发表项。



##### IGMPv3

IGMPv3的成员报告报文的目的地址为224.0.0.22，表示同一网段所有使用IGMPv3的路由器。

通过在报告报文中携带组记录，主机在加入组播组的同时，能够明确要求接收或不接收特定组播源发出的组播数据。



### IPv6

Internet Protocol version 6

#### IPv6地址

IPv6使用128位地址。

1. 冒号十六进制表示：`X:X:X:X:X:X:X:X`。
   - 分为8组，每组16位，用4个十六进制字符表示，组间用`:`隔开。
   - 每组中前导0可以省略，例如`2001:db8:130F:0:0:9C0:876A:130B`。
   - 连续两个以上为0的组可以用双冒号来代替：`2001:db8:130F::9C0:876A:130B`。
     - 一个IPv6地址中只能使用一次双冒号。
2. 地址结构：网络前缀（n位）+接口标识（128-n位），`X:X:X:X:X:X:X:X/n`。
3. 地址分类：
   - 单播地址：唯一标识一个接口。
     - 未指定地址，`::/128`
     - 环回地址，`::1/128`：节点用于将报文发送给自己，类似`127.0.0.1`。
     - 链路本地单播地址，`FE80::/10`：启动时在链路上分配，用于链路上节点通信，不会被转发到其他链路。
     - 唯一本地地址，`FC00::/7`：仅用于同一个站点的地址
     - 全球单播地址：其他地址，通常包括运营商管理的48位前缀和本地16位子网ID和64位接口ID。
   - 任播地址：表示一组接口，发送到任播地址的数据报被传输给该组接口中距离源节点最近的接口。
   - 组播地址：类似IPv4组播地址。IPv6的广播功能使用组播地址来提供。



## 路由协议 RP

Routing Protocol

用于找到源路由器到目的路由器的最佳路径。

路由（实际上是生成路由表的过程）又分为静态路由和动态路由，静态路由通常由管理员进行配置，而动态路由则由机器实时计算。动态计算路由的协议也称为路由选择协议。

自治系统（Autonomous System，AS）指处于一个管理机构下的网络设备群，AS内部网络自治管理，对外提供一个或多个出入口。

自治系统内部的路由协议称为内部网关协议（Interior Gateway Protocol），如RIP、OSPF等；
自治系统外部的路由协议称为外部网关协议（Exteriot Gateway Protocol），如BGP。
上述的三个协议都是路由选择协议。



### 路由信息协议 RIP

Route Information Protocol，基于UDP，是应用层协议。

RIP是基于距离向量的内部网关协议。

1. 跳数：RIP使用跳数（Hop Count）衡量到达目的网络的距离，直接相连网络跳数为1，每经过一个路由器跳数加1，大于等于16的跳数定义为不可达。

   - 跳数最大为15，因此RIP仅适用于小型AS。

2. 路由表项：目的网络IP地址（子网掩码）、跳数、下一跳IP/路由器、信息来源路由器、无效计时器/垃圾回收计时器。

3. RIPv1

   - 有类别：目的网络地址靠A、B、C类地址区分，而不是子网掩码。
   - 广播更新数据报。
   - 不支持手工认证。

4. RIPv2

   - 无类别：传递信息携带子网掩码。
   - 多播更新数据报，地址为224.0.0.9，端口号520。
   - 允许手工认证，加密。

5. 启动：发送Request数据报，请求邻居的路由表，邻居返回Response数据报。

6. 周期更新：每隔30s向外发送一次Response报文。

   - 经过180s没有收到某路由器的更新报文，则将所有来自此路由器的路由信息标志为不可达。
   - 若在其后的120s内仍未收到更新报文，就将该条路由从路由表中删除。

7. 路由表更新算法：距离-向量算法，基于Bellman Ford单源最短路径算法。

   - 对于本地没有的路由信息，直接增加该条目。
   - 本地已有且来源一致的信息，直接更新该条目。
   - 本地已有且来源不一致，则比较开销，选择更新。

8. 避免信息环路：

   水平分割（Split Horizon）、毒性逆转（Poison Reverse）、触发更新（Triggered Updates）

   - 环路举例：R——R1——R2

     - 初始R1存在直连R的距离为1的路由，R2存在经R1到R的距离为2的路由。

     - R和R1断开后，R1收到R2的Response，修改路由表为存在经R2到R的距离为3的路由。

     - R1和R2存在相互指向的、被错误认为去向R的路由。

   - 水平分割：路由器从某个接口学习到的路由信息，不会再从该接口发送出去。

   - 毒性逆转：路由器发送从某个接口学习到的路由信息时，将跳数设为16。

   - 触发更新：当路由器信息改变后，立即发送触发更新信息给相邻路由器。

     - 触发更新仍然不能完全避免上述错误，因此往往和抑制时间结合使用。
     - 抑制时间：网络故障或接口复位时，抑制相应路由，并在抑制时间内不轻易更新路由表。



### 开源最短路径优先 OSPF

Open Shortest Path First，基于IP，是网络层协议。

OSPF是基于链路状态的内部网关协议。OSPFv2针对IPv4，OSPFv3针对IPv6，下述OSPFv2。

1. 路由器ID：OSPF中每个路由器都具有唯一的ID，是32位无符号整数。
   - 路由器ID可以手工或自动配置，在实际中，手工配置使协议更稳定。
2. 路由距离的度量值 Cost：
   - 接口Cost=参考带宽/接口带宽，一般参考带宽取100M，小数向上取整。
   - 一条OSPF路由的Cost为路径上所有接口Cost的总和。
3. OSPF维护的三张表：邻居表、路由表、链路信息数据库（Link State Database，LSDB）。
4. OSPF的五种报文：使用224.0.0.5或224.0.0.6（DR路由器）进行组播。
   - Hello：发现、建立、保活邻居关系
   - Database Description, DD：本地数据库目录
   - Link State Request，LSR：请求查询邻居数据库
   - Link State Update，LSU：答复LSR
   - Link State Ack，LSAck：确认LSU
5. OSPF的七种状态：
   - 无效：还未开始hello包的收发，开始后进入下一状态。
   - 初始：接收到ID不存在本地的hello包，将该邻居置为init状态，相互收发hello，进入下一状态。
   - 双向：此时接收的hello包中ID存在本地，进入双向通信状态。
   - 预启动：使用类似hello的空DD报文进行主从关系选举，ID大者为主。
   - 准交换：使用真正的DD报文进行数据库目录共享。
   - 加载：使用LSR、LSU、LSAck进行LSDB同步。
   - 完全：邻居关系完全建立，不再进行LSDB同步。
6. 路由器类型：
   - 区域内路由器（Internal Router，IR）：所有接口属于一个OSPF区域。
   - 区域边界路由器（Area Border Router，ABR）：属于两个以上区域，其中一个必须是骨干区域。
   - 骨干路由器（Backbone Router，BR）：至少有一个接口属于骨干区域。
   - AS边界路由器（AS Boundary Router，ASBR）：与其他AS交换路由信息的设备。
7. 路由计算：SPF算法



### 边界网关协议 BGP

Border Gateway Protocol，基于TCP，是应用层协议。

不同自治系统AS间交换路由信息的协议，常用于互联网的网关之间。

- 每个AS选择至少一个路由器作为BGP发言人，与其他AS的BGP发言人建立TCP连接，交换信息
- 报文类型：
  - 打开报文
  - 更新报文
  - 保活报文
  - 通知报文
- 先使用打开报文建立关系，若邻站接受则返回保活报文，并周期用保活报文维持关系
