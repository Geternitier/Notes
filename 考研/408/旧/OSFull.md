# OSFull



## 1. 操作系统基础

1. 操作系统：计算机管理软硬件资源、控制程序执行的系统软件。

   - 操作系统是计算机系统最基础的系统软件。

2. 操作系统的特征：并发、共享、虚拟、异步

   - 并发：多个事件在同一时间间隔内发生。
     - 并行：多个事件在同一时刻发生。
   - 共享：资源可供多个并发执行的进程同时使用。
     - 互斥共享：申请与释放
     - 同时访问：可能是分时访问
   - 虚拟：
     - 时分复用：虚拟处理器
     - 空分复用：虚拟存储器
   - 异步：进程是执行、暂停交替的。

3. 操作系统的功能：

   - 管理计算机系统资源：
     - 处理器管理：即进程管理，包括进程控制、同步、通信，死锁处理，处理器调度等
     - 存储器管理：内存分配与回收、地址映射、内存保护与共享、内存扩充
     - 文件管理：文件存储管理、目录管理、读写管理
     - 设备管理：缓冲管理、设备分配与处理、虚拟设备
   - 用户与计算机硬件系统间接口：
     - 命令接口：
       - 联机命令接口：控制台输入、命令解释与执行
       - 脱机命令接口：批处理命令
     - 程序接口：系统调用
   - 扩充计算机资源

4. 操作系统的发展历史：

   - 手工操作
   - 批处理（开始出现操作系统）
     - 单道：自动、顺序
     - 多道：宏观并行，微观串行
   - 分时：将处理器时间分为时间片分配给多任务、多用户进行使用。
   - 实时：在某个时间限制内完成某些任务。具有及时性和可靠性。
   - 网络：结合网络中各台计算机，共享资源，进行通信
   - 分布式：**分布**多个计算机，**并行**完成同一任务
   - 个人

5. 操作系统的运行环境：

   处理器模式：内核态与用户态

   - 内核：时钟、中断、原语、系统控制的数据结构及处理（进程、存储器、设备）
   - 中断与异常：
     - 外中断，也称中断，是来自处理器外的中断
     - 内中断，也称异常，是来自处理器内部的中断，通常是程序执行过程中发生的与当前指令关联的不正常的事件，如访管、硬件故障、程序性异常
   - 中断和异常处理：指令执行周期中检查中断和异常
   - 系统调用：指定调用号，执行Trap，让内核完成涉及资源管理的操作。

6. 操作系统结构：

   - 分层：将OS分为若干层，硬件为0层，每层只能调用相邻的低层服务。
     - 易于逐层调试与扩充
     - 难以合理定义分层，多层调用效率低
   - 模块：按功能进行模块化
     - 增加可理解性和开发速度
   - 内核结构：
     - 宏内核：系统的主要功能模块集中在内核中
     - 微内核：保留基本功能，其余功能作为用户态的服务器与内核进行通信。

7. 操作系统的引导：

   - CPU读取运行boot程序，加载操作系统内核，执行操作系统初始化程序

8. 虚拟机：通过虚拟化层逻辑化原先的物理设备，实现软硬件解耦。

   - 硬件级虚拟化（Hypervisor）：CPU、内存、I/O设备
   - 操作系统级虚拟化（Docker、VMWare WorkStation）



## 2. 处理器管理

1. 处理器：算术逻辑单元、控制单元、各种寄存器

   - 用户程序可见寄存器：地址和数据寄存器
   - 控制与状态寄存器：程序计数器和指令寄存器、各种标志位寄存器（处理器模式、中断）
     - 程序状态字：包含当前程序的控制与状态信息。

   机器指令的执行：取指、译码、执行

   处理器模式与特权指令：内核模式可执行全部指令，用户模式只能执行非特权指令。

2. 进程：具有一定独立功能的程序关于某个数据集合的一次运行活动。

   - 进程是操作系统进行资源分配和调度的基本单位。

   进程控制块：描述进程基本情况和运行状态的数据结构。

   - 通常包含信息：
     - 进程描述信息：进程ID、用户ID
     - 进程控制信息：状态、优先级、信号量、CPU占用时间、进入内存时间等
     - 资源分配信息：段指针、文件描述符
     - 处理器相关信息：CPU各寄存器的值

   进程映像（进程实体）：进程控制块、程序段、相关数据段

3. 进程的状态：

   三态模型：运行、就绪、等待

   - 就绪态$\rightarrow$运行态：处理器空闲时选择、优先进程抢占
   - 运行态$\rightarrow$等待态：等待资源、输入输出、信号
   - 等待态$\rightarrow$就绪态：资源满足、输入输出结束、信号完成
   - 运行态$\rightarrow$就绪态：运行时间片到、优先进程抢占

   此外，也有短暂的新建态（资源分配）和结束态（资源回收），但并不属于三态模型的循环中。

   进程控制：

   - 进程创建：终端用户登录、作业调度、系统提供服务、用户程序请求
     - 分配进程ID，申请进程控制块。
     - 分配资源，初始化进程控制块。
     - 设为就绪态。
   - 进程终止：正常结束、错误终止、外界干预
     - 检查进程状态
     - 释放进程资源
     - 删除进程控制块
   - 进程阻塞：等待某些操作完成
   - 进程切换：
     - 挂起进程，保存CPU上下文到进程控制块
     - 加载新进程的CPU上下文，执行新进程

4. 进程通信：

   - 共享存储
   - 消息传递：直接（发送给对应进程）、间接（信箱）
   - 管道：生产-消费形式通信

5. 线程：进程的一条执行路径。

   单进程的问题：进程切换、通信开销大；进程并发粒度受限，并行计算效率低

   多线程环境：进程是操作系统中进行资源分配与保护的独立单位，线程是调度的基本单位。

   - 线程的状态：就绪、运行、等待
   - 线程的组织：线程控制块（线程标识符、控制信息、处理器相关信息、资源信息）

   线程的实现：

   - 用户级线程：用户程序提供多线程环境，进行线程管理，内核不知线程的存在

     特点：

     - 线程切换不需要模式切换，系统开销小
     - 允许进程按特定需要选择调度算法
     - 能运行在任何操作系统上
     - 不能利用多处理器，操作系统调度进程，只有一个ULT能执行
     - 一个ULT的阻塞将引起整个进程的阻塞

   - 内核级线程：操作系统内核管理与调度线程、提供使用线程的程序设计接口

     特点：

     - 进程的一个线程阻塞，内核能调度同一进程的其他线程运行
     - 多处理器环境中，内核能同时调度同一进程的多个线程并行执行
     - 内核自身也可用多线程技术实现，提高操作系统执行速度和效率
     - 应用程序线程在用户态而线程调度在内核态，因而线程切换需要模式切换，系统开销大

   - 混合式线程：建立内核级线程和用户级线程间的映射关系

6. 处理器调度：选择进程分配处理器运行。

   - 调度层次：
     - 高级调度：决定能否加入执行的进程池中
       - 创建进程
     - 中级调度：决定主存中的可用进程集合
       - 进程挂起与恢复

     - 低级调度：决定哪个进程占用处理器执行
       - 按某种原则将处理器分配给就绪态进程或内核级线程。
   - 调度时机：
     - 决定两个就绪的进程谁先执行
     - 进程结束/挂起后调度进程执行
     - 决定是否抢占
     - 时间片轮转
   - 调度衡量指标：
     - CPU利用率：$\frac{CPU工作时间}{CPU工作时间+CPU等待时间}$
     - 系统吞吐量：单位时间内CPU完成作业数
     - 周转时间：$作业完成时刻-作业提交时刻$
   - 调度算法：
     - 先来先服务$FCFS$：长作业会让短作业等待很久，有利于CPU繁忙型作业
     - 短作业优先$SJF$：长作业饥饿
     - 高响应比优先：响应比$=\frac{等待时间+工作时间}{工作时间}$。
     - 优先级调度：静态优先级与动态优先级
       - 优先级设置：系统$>$用户，交互$>$非交互，IO$>$计算。
     - 时间片轮转
     - 多级队列：不同队列使用不同调度算法
       - 多级反馈队列：动态优先级



## 3. 内存管理

1. 程序装入内存：

   - 编译

   - 链接

     - 静态链接：编译后，将需要的模块链接成一个完整的装入模块。
     - 装入时动态链接：编译后，在装入时边装入边链接。
     - 运行时动态链接：程序执行前才进行链接，未用到的模块都不会先调入内存和链接。

   - 装入

     - 绝对装入：将程序装入选定的内存地址。

     - 可重定位装入：链接后程序中地址都是相对于起始地址的相对地址，装入时修改相对地址。

     - 动态运行时装入：程序在内存中可以移动，程序中相对地址的修改在程序执行前才进行。

2. 逻辑与物理地址：

   逻辑地址：用户编程所使用的地址空间，从0开始编号，也称相对地址。

   物理地址：内存物理单元的集合，进程通过物理地址在内存中进行存取。

   - 可装入程序将代码装入内存时进行地址转换，将逻辑地址转换为物理地址，称为地址重定位。

3. 内存保护：

   - 上下限寄存器：存储用户进程在内存中的上下限地址。
   - 基址+限长寄存器：存储进程的起始地址和最大逻辑地址。

4. 内存分配：

   单连续分区管理：每个进程占用一个物理上完全连续的存储空间。

   - 单用户连续分区

     - 主存区域划分为系统区和用户区
     - 设置一个栅栏寄存器界分两个区域，进行存储保护
       - 一般使用静态重定位进行地址转换

   - 固定分区

     - 支持多个数量、大小固定的分区

     - 使用主存分配表(分区号，起始地址，长度，占用标志)，执行主存分配/去配。
       - 会产生内存内零头，即内存分区中空闲的部分。

   - 可变分区

     - 创建进程时，根据进程所需主存查看主存中是否有足够空闲空间，有则分配，无则等待。
       - 设置链表形式的已分配和未分配区表
       - 产生外部碎片：移动进程位置，需要动态重定位支撑。
     - 可变分区顺序分配算法：
       - 最先适应：通常性能最好
       - 邻近适应：从上次查找结束的地方开始查找，导致高地址的大分区减少
       - 最优适应：最小空闲分区，外部碎片最多
       - 最坏适应：最大空闲分区，导致无大分区可用
     - 可变分区索引分配算法：设置索引表管理过长的空闲分区链表，每个分区大小为一个索引
       - 快速适应：适配的最小分区索引的第一个分区。
       - 哈希：构建关键字为分区大小的哈希表。
       - 伙伴系统：当需要分配大小为$n,2^{i-1}\lt i\lt 2^i$的分区，查找大小为$2^i$的分区链，若有则分配；若无，查找$2^{i+1}$的分区链。若有，将其分为两个$2^i$的分区，这两个分区称为伙伴，其中一个进行分配，另一个加入$2^i$的分区链；若无，类推。

   分页存储管理：

   1. 将物理地址划分为多个大小相等的页架，逻辑地址被页架分成页。

      - 逻辑地址包含页号和页内偏移地址。

   2. 不同的页可以放在不同页架中，不需要连续。

   3. 为每个进程建立页表，每个页表项包含页号和其对应的物理块号。

      - 地址转换：检查地址是否超限；查找页表，将逻辑地址的页号转换为物理块号。

      - **快表**：分页地址访问需要查页表+查地址两次内存访问，在地址转换机构中增设快表存放部分表项以减少一次内存访问。
      - 多级页表：用页目录来记录多个页表的位置。

   分段存储管理：

   1. 每个程序由若干段组成，每一段都可以从0开始编址，段内的地址是连续的。
      - 逻辑地址包含段号和段内偏移量，是二维地址。
   2. 每个进程设置一张段表，每个段表项记录段号、段长和起始地址。
      - 地址转换：检查地址是否超限；查找段表，将逻辑地址的段号转换为段起始地址。

   段页式存储管理：

   1. 每个进程由若干段组成，每个段存储在多个页中。

      - 逻辑地址包含段号、页号、页内偏移量

   2. 每个进程设置一张段表，每个段表项包含段号、页表长度和页表地址。

      - 地址转换：

        检查地址超限，查段表获得页表，检查地址超限，查页表获得物理块号，加上页内偏移完成。

5. 内存扩充：虚拟内存

   局部性原理：时间（相同存储单元局部时间内集中访问）、空间（局部空间内存储单元集中访问）

   实现方式：把进程全部内容装入虚拟存储器，执行时部分装入实际内存，根据执行动态调入调出内容。

   请求页式存储管理：

   1. 在页表项中添加标记位（是否调入、是否修改）等。
   2. 访问的页面不在内存，触发缺页中断，调入页面。
   3. 若页面已满，选择页面进行置换。

   - 页面分配策略：
     - 固定分配 局部置换：为进程分配固定数目物理块，在其中进行置换。
       - 固定分配方法：平均、大小比例、优先级
     - 可变分配 局部置换：为进程分配一定数目物理块，在其中进行置换，如果缺页率高，就再分配一些物理块，反之就减少一些物理块。
     - 可变分配 全局置换：为进程分配一定数目物理块，缺页则再分配物理块

   - 页面置换算法：

     - OPT页面调度算法

       - 由Belady提出，又称Belady算法。

       - 只可模拟，不可实现。

       当要调入新页面时，先淘汰以后不再访问的页，后选择距现在最长时间后再访问的页。

     - 先进先出算法(FIFO)：总是淘汰最先调入主存的页

       - 进程分配的物理块增多，缺页次数可能会增加，称为Belady异常。

     - 最近最少用算法(LRU)：淘汰最近最久未被访问的页

       - 严格实现的代价大：维持特殊队列

     - 最不常用算法(LFU)：淘汰最近一段时间内访问次数较少的页

     - 时钟调度算法：用循环队列构造页面队列，队列指针指向可能要淘汰的页

       1. 页面调入主存时，引用标志位被置为1
       2. 访问主存页面时，引用标志位被置为1
       3. 淘汰页面时，从指针当前指向的页面开始扫描循环队列
          - 将所遇到的引用标志位是1的页面的引用标志位清0，跳过
          - 将所遇到的引用标志位是0的页面淘汰，指针推进

   - 抖动：同一页面短时间内被反复调入调出。

     驻留集：给进程分配的页框的集合。

     工作集：某段时间间隔内，进程访问的页面集合。

     缺页中断率：运行中成功访问次数$S$，不成功访问次数$F$，总访问次数$A=S+F$，缺页中断率为：$f=F/A$。

6. 带有快表的页式地址转换：

   1. 按逻辑地址中的页号查快表
   2. 若在快表中，则由页架号和单元号生成绝对地址
   3. 不在快表中，再查主存页表形成绝对地址，同时登记该页到快表中
   4. 快表填满后，按一定策略淘汰一个旧登记项，登记新页

7. 带有快表的段页式地址转换：

   - 根据逻辑地址中的页号查快表，存在则形成绝对地址。
   - 查段表，判断是否访问超限，存在则获得页表地址。
   - 查页表，判断是否访问超限，存在则获得页的物理地址。
   - 缺页中断。



## 4. 文件管理

1. 文件控制块：文件名称、类型、大小、权限、数据指针

   文件目录项：文件控制块/文件名称+文件索引结点

   - 文件索引结点：文件标识符、类型、权限、物理地址

2. 文件操作：

   - 创建：分配外存空间，新建文件目录项
   - 删除：删除文件目录项，回收外存空间
   - 打开：将目录项/文件控制块写入内存中的打开文件表
   - 关闭：从打开文件表删除该文件
   - 读写：查找该文件，并使用目录项中对应的指针进行读写操作

3. 文件保护：

   - 访问类型：读、写、执行、追加、删除、列出信息等
   - 访问控制：对拥有者、组和其他这三种用户类型进行访问类型限制。

4. 文件的逻辑结构：

   - 流式文件：一串依次的字节组成的信息流序列。
   - 记录式文件：有结构的若干逻辑记录信息所组成的记录流文件。

5. 文件的物理结构：

   - 顺序文件：文件中逻辑上连续的信息存放到存储介质相邻的块中形成顺序结构，也称连续文件。
   - 连接文件：使用连接字来表示文件中各个物理块之间的先后次序。
     - 隐式：第一块文件信息的物理地址由文件目录给出，每一块的连接字指出下一个物理块位置。
     - 显式：使用文件分配表记录每个物理块位置。
   - 索引文件：每个文件建立一张索引表，每个表目包含一个记录的键（逻辑记录号）及其存储地址。
   - 直接文件：又称散列文件，通过计算记录的关键字建立与其物理存储地址之间的对应关系。

6. 文件目录：按名检索、存取、共享文件，

   - 目录结构：
     - 单级目录：每个文件控制块占一个目录项
     - 二级目录：主文件目录下每个目录项为一个单级目录
     - 树形目录
     - 无环图目录：在树形目录下新增文件共享的支持
   - 目录操作：搜索、创建文件、删除文件、创建目录、删除目录、移动目录、修改目录、列出信息
   - 目录实现：线性表、散列表
   - 文件共享：
     - 硬链接：基于索引，文件信息存放在索引中，新增硬链接即新增索引中链接记数。
     - 软链接：被链接文件的路径

7. 文件系统：

   - 实现结构：
     - 用户接口：接受系统调用，进行语法检查，进入逻辑文件控制子系统
     - 逻辑文件控制子系统：根据文件路径名，搜索文件目录，建立活动文件表，根据文件结构和存取方法，把逻辑记录转换成相对物理块号和块内相对地址
     - 文件保护子系统：识别调用者身份，验证存取权限，判定本次文件操作的合法性
     - 物理文件控制子系统：实现缓冲区管理，根据物理结构，将对应相对物理块号转换为实际物理块号，负责文件存储空间的分配，输入/输出控制系统调用形式
     - 输入/输出控制子系统：执行具体的物理块输入/输出操作
   - 外存空间管理
     - 分配：
       - 连续分配：存放在辅存空间连续存储区中（连续的存储块号）
         - 优点是顺序访问速度快，管理简单
         - 为了获得足够大的连续存储区，需要定时进行碎片整理
       - 非连续分配：动态分配给若干扇区或簇，不要求连续
         - 辅存空间管理效率高，便于文件动态增长和收缩
     - 空闲块管理：
       - 连续分配：空闲表
       - 非连续分配：空闲链表
         - 位示图：使用若干字节构成一张表，表中每一字位对应一个物理块，字位的顺序和块的相对次序一致，字位为1表示相应块已占用，字位为0表示该块空闲。
         - 成组链接法（将空闲块分组，每组为一个链表，空闲盘块号栈）
   - 虚拟文件系统：屏蔽不同文件系统差异，提供统一操作接口
     - 超级块：包含文件系统信息
     - 索引结点
     - 目录项
     - 文件对象



## 5. 设备管理

1. 设备：又称外围设备、外设，用于计算机系统与外部世界的信息交换或存储。

   设备的分类：

   - 信息传输：分为输入设备、输出设备和输入输出设备
   - 共享属性：独占设备、共享设备、虚拟设备
   - 信息单位：字符设备、块设备

2. 输入/输出控制：

   设备控制器：CPU与设备之间的接口。

   - 接受和识别CPU或通道发来的命令
   - 实现数据交换
   - 发现和记录设备及其自身的状态信息，供CPU处理时使用
   - 当连接多台设备时，识别设备地址

   输入/输出控制方式：

   - 轮询：CPU发出指令，然后循环检查设备状态至完成
   - 中断：进程发出指令后挂起，收到设备的中断后再执行
   - 直接存储器存取，DMA：使用DMA模块替代处理器来控制主存和设备控制器间的数据交换
     - 处理器向DMA模块发送指令，DMA完成内存和设备的数据交换，然后发送中断信号
     - 和中断方式的区别：DMA使用数据块进行传输，数据传输不经过CPU
   - 通道：处理器不再执行输入/输出指令，而是在主存中组织通道程序，由输入/输出通道执行。
     - 通道可控制多台同类或不同类设备。

3. 输入/输出软件层次：

   - 中断处理程序
   - 设备驱动程序
   - 独立于设备的软件：向用户层软件提供一致性接口
     - 设备独立性：不指定物理设备，而是指定逻辑设备，使得用户进程和物理设备分离
   - 用户空间软件

4. 输入/输出缓冲：在内存中开辟存储区，专门用于临时存放输入/输出操作的数据。

   - 单缓冲：在主存系统区中开设一个缓冲区。

   - 双缓冲：在主存系统区开设两个缓冲区。

     - 输入：先把数据输入缓冲区1，再从缓冲区1把数据传到用户区，供应用程序处理

       （同时设备可将数据传送到缓冲区2）

     - 输出：先将数据从用户区传送到缓冲区1，再将数据传送到设备

       （同时应用程序可将数据传送到缓冲区2）

   - 循环缓冲：分配一组缓冲区，每个缓冲区有指向下一个缓冲区的链接指针，构成循环。

   SPOOLing技术：缓解CPU高速与设备低速的矛盾。

   - 磁盘上开辟输入井和输出井两个存储区域，内存中开辟输入和输出两个缓冲区。

   - 输入缓冲区暂存输入设备输入的数据，后传送到输入井；

     输出缓冲区暂存输出井送来的数据，后传送给输出设备。

   - 输入进程控制输入数据的传输，CPU需要时将数据从输入井读入内存；

     输出进程等待输出设备就绪后将输出井中数据经缓冲区传送给设备。

   - 井管理程序：控制作业与井之间信息的交换。

5. 设备分配：

   - 设备控制表：表项包含设备类型、标识符、状态、控制器表指针
   - 控制器控制表
   - 通道控制表
   - 系统设备表：唯一，记录连接到系统的所有人物理设备。

   考虑因素：

   - 设备属性：
     - 独占设备：只能分配给一个进程
     - 共享设备：可分配给多个进程，但需要合理调度访问次序
     - 虚拟设备：可同时分配给多个进程
   - 分配算法：
     - 先来先服务
     - 优先级
     - 安全性（例如防止死锁）
   - 分配过程：先分配设备，然后分配设备控制器，最后分配通道。

   逻辑设备和物理设备的映射：使用唯一的逻辑设备表来记录逻辑设备到物理设备的映射。

   - 表项：逻辑设备名、物理设备名、驱动程序入口

6. 磁盘：

   - 磁盘的结构：

     - 磁盘一般由多个盘片组成，每个盘片一般有两个盘面
     - 盘面包括多个同心圆结构的磁道，不同盘面上位于相同位置的磁道构成柱面
     - 每个磁道分为固定多个扇区，相邻扇区组合成簇
     - 物理块的地址：柱面号，磁道号，扇区号

   - 磁盘的读写：磁头定位到指定磁道上的指定扇区的开始处

     1. 寻道：控制移动臂到达指定柱面
     2. 旋转：等待要读写的扇区旋转到磁头下
     3. 选择磁头号，进行数据传送

     存取时间：寻道时间、旋转延迟、传送时间的总和：$T_a=T_s+\frac{1}{2r}+\frac{b}{rN}$。

     其中，$T_a$为存取时间，$T_s$为寻道时间，$r$为磁盘旋转速度（转/秒），$b$为要传送的字节数，$N$为一个磁道中的字节数。

   - 驱动调度算法：

     - 移臂调度：使移动臂的移动时间最短以减少寻道总时间
       - 先来先服务：移臂距离大，性能差
       - 最短查找时间优先：先执行查找时间最短的请求，寻道性能较好
         - 存在“饥饿”现象
       - 单向扫描：移动臂向一个方向扫描，归途不提供服务
       - 双向扫描：移动臂向一个方向移动，到达最后一个柱面再向反方向移动
       - 电梯调度：改进双向扫描，当前移动方向没有访问请求时就改变方向
     - 旋转调度：使旋转延迟的总时间最少
       - 循环排序：

         - 通过优化输入/输出请求排序，在最少旋转圈数内完成位于同一柱面的访问请求

         - 旋转位置测定硬件和多磁头同时读写技术有利于提高旋转调度的效率

       - 优化分布：

         - 通过信息在存储空间的排列方式来减少旋转延迟
         - 交替排序：由于磁盘匀速旋转，可能处理当前扇区数据时，下个扇区已经跳过。因此，可对扇区间隔编号，交叉因子为n:1表示相邻编号间间隔n-1个扇区
         - 相邻扇区集中成簇读写
         - 按柱面集中存储数据，可以减少数据读写时的移臂操作



## 6. 并发控制

1. 并发程序设计：

   一个程序分成若干个可同时执行的程序模块，每个程序模块和它执行时所处理的数据组成一个进程。

   并发进程的分类：无关的、交互的

   - 无关的并发进程：一个进程的执行与其他并发进程的进展无关

     - 并发进程的无关性是进程的执行与时间无关的一个充分条件，又称为Bernstein条件

       - 程序$p_i$在执行期间引用的变量集，记为$R(p_i)=\{a_{i1},a_{i2},...,a_{in}\}$，	

       - 程序$p_i$在执行期间改变的变量集，记为$W(p_i)=\{b_{i1},b_{i2},...,b_{im}\}$

       - 若两个进程的程序$p_1$和$p_2$能满足Beinstein条件，即满足

         $(R(p_1)\cap W(p_2))\cup (R(p_2)\cap W(p_1))\cup (W(p_1)\cap W(p_2))=\varnothing$，

         则这两个并发进程的执行与时间无关

   - 交互的并发进程：一个进程的执行可能影响其他并发进程的结果

     - 两种基本关系：竞争、协作

       - 竞争：一个进程分配得到资源，另一个等待
         - 竞争带来的两个基本问题：死锁和饥饿
         - 解决方法：互斥
       - 协作：不同进程按一定的协调次序执行任务
         - 解决方法：同步，基于某个条件来协调它们的活动

2. 临界区管理：并发进程中与共享变量有关的程序段称为临界区，共享变量代表的资源称为临界资源。

   临界区互斥准则：

   - 空闲让进：临界区空闲时允许请求的进程进入
   - 忙则等待：已有进程进入临界区，其他进程等待
   - 有限等待：有限时间内等待
   - 让权等待：进程不能进入临界区则挂起等待

   软件实现的Peterson算法

   ```
   bool inside[2];
   inside[0] = false;
   inside[1] = false;
   enum {0,1} turn;
   
   cobegin
   process P0(){
   	inside[0] = true;
   	turn = 1;
   	while(inside[1]&&turn==1);
   	{临界区};
   	inside[0] = false;
   }
   process P1(){
   	inside[1] = true;
   	while(inside[0]&&turn==0)
   	{临界区};
   	inside[1] = false;
   }
   coend
   ```

   硬件实现：关中断（无法切换进程）、测试并建立TestAndSet（TS）、Swap

   ```
   //TS指令实现进程互斥
   bool TS(bool &x){
     if(x){
       x = false;
       return true;
     } else return false;
   }
   
   bool s = true;
   
   cobegin
   process Pi(){
     while(!TS(s)); //上锁
     {临界区};
     s = true;      //开锁
   }
   coend
   ```

   ```
   //对换指令实现进程互斥
   void SWAP(bool &a, bool &b){
   	bool temp = a;
   	a = b;
   	b = temp;
   }
   
   bool lock = false;
   
   cobegin
   Process Pi(){
   	bool key = true;
   	do{
   		SWAP(key, lock);
   	}while(key);		//上锁
   	{临界区};
   	SWAP{key, lock};//开锁
   }
   ```

   互斥锁：进入临界区时循环调用获取锁，退出时释放锁。

   以上方法都不满足 让权等待。

   信号量和PV操作：设s为一个记录型数据结构，一个分量为整型量value，另一个为信号量队列。

   P和V操作原语的定义：

   - P(s)：将信号量s减去1，若结果小于0，则调用P(s)的进程被设置成等待信号量s的状态
   - V(s)：将信号量s加1，若结果不大于0，则释放一个等待信号量s的进程，其转为就绪态

   对于信号量，只允许使用P和V原语操作访问，不能直接对信号量的整型值和队列作操作。

   管程：由局部于自己的若干公共变量及其说明和所有访问这些公共变量的过程所组成的软件模块。

   条件变量：只有在管程中才能被访问，它对管程内所有过程是全局的，只能通过两个原语操作来控制

   - wait()：阻塞调用进程并释放管程，直到另一个进程在该条件变量上执行signal()
   - signal()：释放由于对条件变量执行wait()而被阻塞的其他进程，若无，信号不被保存

3. 死锁：一个进程集合中的每一个进程都在等待只能由该集合中的其他进程才能引发的事件。

   - 四个必要条件

     - 互斥条件：系统中存在进程应互斥使用的临界资源

     - 占有和等待条件：进程请求资源不得到满足而等待时，不释放已占有的资源

     - 不剥夺条件：已被占有的资源只能被属主释放，不允许被其他进程剥夺

     - 循环等待条件：存在循环等待链，每个进程都在链中等待下一个进程所持有的资源

   - 处理策略：预防、避免、检测并解除

   死锁的预防：

   - 破坏互斥条件：使资源可同时访问而不是互斥使用
   - 破坏占有和等待条件：静态分配
   - 破坏不剥夺条件：剥夺式调度
   - 上述方法均导致资源利用率和吞吐率低

   死锁的避免：银行家算法

   1. 系统中的所有进程进入进程集合。
   2. 在安全状态下系统收到进程的资源请求后，先把资源试探性分配给它。
   3. 系统用剩下的可用资源和进程集合中其他进程还要的资源数作比较，在进程集合中找到剩余资源能满足最大需求量的进程，从而保证这个进程运行完毕并归还全部资源。
   4. 把这个进程从集合中去掉, 系统的剩余资源更多了。反复执行上述步骤。

   5. 最后，检查进程集合，若为空表明本次申请可行，系统处于安全状态,可实施本次分配；否则，有进程执行不完，系统处于不安全状态，本次资源分配暂不实施，让申请进程等待。

   死锁的检测和解除：

   - 检测：资源分配图，圆圈表示进程，方框代表资源，框中的一个圆代表一类资源中的一个。

     - 约定$P_i\rightarrow R_j$为请求边，表示进程$P_i$申请资源类$R_j$中的一个资源得不到满足而处于等待$R_j$类资源的状态，该有向边从进程开始指到方框的边缘，表示进程$P_i$申请$R_j$中的一个资源。
     - 约定$R_j \rightarrow P_i$为分配边，表示$R_j$类中的一个资源已被进程$P_i$占用。由于已把一个具体的资源分配给了进程$P_i$，故该有向边从方框内的某个黑圆点出发指向进程。

     如果能在进程-资源分配图中消去此进程的所有请求边和分配边，成为孤立结点，经一系列简化，使所有进程成为孤立结点，则该图是可完全简化的。

     - 系统为死锁状态的充分条件是，此进程-资源分配图是不可完全简化的

   - 解除：

     - 结束所有进程。
     - 撤销陷于死锁的所有进程。

     - 逐个撤销陷于死锁的进程，回收其资源重新分派，直至死锁解除。

     - 剥夺陷于死锁的进程占用的资源，但并不撤销它，直至死锁解除。
       - 可仿照撤销陷于死锁进程的条件来选择剥夺资源的进程

     - 根据系统保存的检查点，让所有进程回退，直到足以解除死锁
       - 要求系统建立保存检查点、 回退及重启机制。

     - 当检测到死锁时，可能存在某些未卷入死锁的进程，随着这些进程执行到结束，有可能释放足够的资源来解除死锁。
