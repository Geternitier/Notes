# 处理器



## 1. 指令

处理器负责逐条读取指令并执行，基本流程包含「取指、译码、取数、执行、写回」等。

### 1.1 指令组成

#### 指令格式

**机器指令**是一串二进制位，通过译码器控制电路执行。

1. 指明操作类型的位称为**操作位**，指明数据来源的位称为**地址位**；
2. 操作位数固定的指令称为**定长操作位指令**，例如8位指令中，前4位指定操作；
3. 操作位数可变的指令称为**可变操作位指令**，例如8位指令：
   1. 前 4 位 1111，则为 0 地址指令，操作位占 8 位；
   2. 前 4 位 0000～1110，则为 1 地址指令，地址位占后 4 位。



#### 寻址方式

确定操作数地址的过程称为**寻址**。

1. **立即寻址**：地址位是操作数本身。
2. **隐含寻址**：指令不含操作数地址，默认取某寄存器或栈顶的操作数；
3. **直接寻址**：地址位是内存地址或寄存器号，操作数在该内存单元或寄存器；
4. **间接寻址**：地址位是内存地址或寄存器号，操作数的内存地址在该内存单元或寄存器；
5. **相对寻址**：地址位为相对地址，和某地址相加后得到目的地址；
   1. 转移时，常用「目的指令地址=当前指令地址+当前指令长度+相对地址」。
   2. **基址寻址**：基址寄存器中基址+相对地址；常用于虚拟地址转换为物理地址。
   3. **变址寻址**：变址寄存器中变址+相对地址；常用于数组遍历、循环处理。



### 1.2 指令控制

#### 控制器

控制器负责产生电路控制信号，控制指令执行。

1. **硬布线控制器**也称组合逻辑控制器，由数字逻辑电路根据指令操作码、时序信号、状态标志产生控制信号。
2. **微程序控制器**将机器指令转化为**微程序**。

硬布线快，但不能修改，适用于简单、高频指令；微程序灵活，但慢，适用于复杂指令。



#### 微程序

1. 微命令：最基本的控制信号，如`PCout`、`MemR`；
2. 微指令：若干微命令的组合；
   1. 微指令存储在**控制存储器 CM**，一般为ROM；
   2. 取出并执行一条微指令的平均时间称为**微周期**。
   3. 微指令从CM读取到微IR中，经译码产生控制信号。
3. 微程序：完成一条机器指令的微指令序列。



**微命令编码**：

1. 可定义多个微命令的微指令称为**水平型微指令**：
   1. **直接编码**：一位代表一个微命令；
   2. **字段直接编码**：控制位分组，每组译码微命令；
      1. 例如共4位控制位，2位控制PC，2位控制ALU；
      2. 组内微命令互斥；例如前2位中，01表示PCout，10表示PCin；
      3. 组间微命令并行。例如前2位PCout，后2位ALUadd。
   3. **字段间接编码**：一个字段的译码由另一个字段位控制。
2. 操作位译码对应单条微命令的微指令称为**垂直型微指令**。

水平型微指令的程序短，并行强，但指令长，难编写。



**微指令地址形成**：

1. 微程序入口微指令地址：由机器指令的操作位映射。
2. 下一条微指令地址：顺序指令常用自增，转移指令常用断定。
   3. $\mu$PC自增；
   4. **断定**：微指令包含下地址字段；CM中固定，但可通过电路指明其他地址。



### 1.3 指令周期

#### 指令周期

取指并执行的全部时间称为**指令周期**，可分为下述部分：

1. 取指周期：根据PC读取指令到IR。
   1. **程序计数器 PC**：保存将执行的指令的地址；
   2. **指令寄存器 IR**：保存正在执行的指令；
   3. **指令译码器 ID**：翻译指令为电路操作。
2. 间址周期：取操作数的有效地址。
   1. **通用寄存器 GPR**：通用的操作数寄存器；
   2. **存储地址寄存器 MAR**；
   3. **存储数据寄存器 MDR**。
3. 执行周期：取操作数，执行指令。
4. 中断周期：检查是否有中断请求并处理。



根据指令周期和时钟周期的关系，可划分三类处理器：

1. 单周期处理器：一个时钟周期执行一条指令，时钟周期由延迟最高的指令确定；
2. 多周期处理器：多个时钟周期执行一条指令，指令串行执行；
3. **流水线处理器**：
   1. 将指令周期划分为多个阶段，每个阶段在一个时钟周期内完成；
   2. 每个时钟周期启动一条指令，处于不同阶段的指令并行执行。



#### 指令流水线

流水线对指令的要求：

1. 长度一致，格式规整；
2. 使用load/store指令访存；
3. 数据和指令边界对齐。



相邻指令的依赖关系会引发**流水线冒险**：

1. **结构冒险**：不同指令同时争用相同功能部件。
2. **数据冒险**：后面指令使用前面指令的结果。
3. **控制冒险**：转移指令和返回指令改变PC值造成控制冲突。

处理方式：

1. 结构冒险：暂停后一条指令；用多个功能部件。
2. 数据冒险：
   1. 插入空指令，延迟后一条指令；
   2. 编译优化；
   3. **转发/旁路**：生成的计算结果直接转发到ALU，而不经过寄存器。
3. 结构冒险：
   1. 在转移指令前插入空指令；
   2. 分支预测，提前生成转移地址。



高级指令流水线技术：

1. **超流水线**：增加流水线级数使更多指令在流水线中。
2. **超标量流水线**：动态多发射，同时执行多条指令。使用分支预测可以实现乱序执行。
3. **超长指令字**：编译时挖掘指令并行性，形成超长指令。



### 1.4 指令集

**指令集架构 Instruction Set Architecture ISA**规定了硬件提供的编程接口，包含

1. 指令格式、寻址方式、操作类型；
2. 程序可见寄存器类型和数量，存储空间大小和编址；



按指令系统复杂度，计算机可分为**复杂指令系统计算机 CISC**和**精简指令系统计算机 RISC**。

CISC：

1. 指令系统复杂，指令长度不固定、格式多，使用频度差距大；
2. 指令执行时间差距大，多数指令需多个时钟周期完成；
3. 多采用微程序控制。

RISC：

1. 用简单、高频指令，组合实现复杂功能，指令长度固定，格式少；
2. 硬布线控制为主。



## 2. 处理器管理

### 2.1 进程

#### 概念

**进程 Process**是OS控制程序运行的数据结构，是OS资源分配和调度的基本单位。

1. **进程映像**是进程的内存实体，包含进程控制块、代码段、数据段、堆栈段；
2. **进程控制块 PCB**是描述进程情况和状态的数据结构。
   1. 标识：进程ID、父进程ID、用户ID；
   2. 控制信息：状态、优先级、信号量、CPU占用时间、进入内存时间等；
   3. 资源信息：段指针、文件描述符；
   4. 执行信息：通用寄存器、程序计数器、程序状态字、栈指针。



#### 状态

进程的状态包含**就绪**、**运行**、**阻塞**。

1. 就绪态$\rightarrow$运行态：调度执行、优先抢占；
2. 运行态$\rightarrow$阻塞态：等待资源；
3. 阻塞态$\rightarrow$就绪态：资源满足；
4. 运行态$\rightarrow$就绪态：运行时间片结束、被抢占。

进程控制：

1. 进程创建：分配ID，申请PCB；分配资源，初始化PCB；设为就绪态。
2. 进程终止：检查状态，释放资源，删除 PCB
3. 进程阻塞：等待某些操作完成
4. 进程切换：挂起进程，保存上下文；加载新进程上下文，执行。



#### 通信

**进程通信 IPC**的方式：

1. 共享存储；
2. 消息传递：直接（发送给对应进程）、间接（信箱）；
3. 管道：使用内存缓冲区进行通信。



### 2.2 调度

#### 调度

**处理器调度**是选择进程分配处理器执行的过程。

调度算法：

1. **先来先服务 FCFS**：长作业会让短作业等待很久，有利于CPU繁忙型作业
2. **短作业优先 SJF**：长作业饥饿
3. **高响应比优先**：响应比$=\frac{等待时间+工作时间}{工作时间}$。
4. **时间片轮转**
5. **优先级调度**：静态优先级与动态优先级
   - 优先级设置：系统$>$用户，交互$>$非交互，IO$>$计算。
6. **多级队列**：不同队列使用不同调度算法
   - 多级反馈队列：动态优先级

调度衡量指标：

1. CPU利用率：工作时间/(工作时间+等待时间)；
2. 系统吞吐量：单位时间内CPU完成作业数；
3. 周转时间：作业从提交到完成的时间间隔。



调度层次：

1. 高级调度：新建和结束进程，决定进程能否加入执行的进程池中；
2. 中级调度：进程挂起与恢复，决定内存中的可用进程集合；

3. 低级调度：处理器分配，决定哪个进程占用处理器执行。



#### 线程

进程切换、通信开销大；并发粒度受限，并行计算效率低。因此引入线程。

**线程**是进程的一条执行路径，是调度的基本单位。

1. 线程的状态：就绪、运行、等待
2. 线程的组织：线程控制块（线程标识符、控制信息、处理器相关信息、资源信息）

线程的实现：

1. **用户级线程 ULT**：用户程序提供多线程和线程管理
   1. 调度算法自选，能运行在任何 OS，线程切换不经内核从而开销小
   2. 不能利用多处理器，只能执行一个 ULT，且 ULT 阻塞可能使整个进程阻塞
2. **内核级线程 KLT**：内核提供多线程和线程管理，用户程序调用线程 API
   1. 能利用多处理器同时执行多个 KLT，KLT 阻塞不导致整个进程阻塞
   2. 线程切换需经过内核，开销大
3. $M:N$模型：建立 KLT 和 ULT 的动态映射关系，两层调度。

go 语言通过 GMP 调度器将 goroutine 分配到内核线程上执行，既能执行大量ULT，也减少了内核切换的开销。



### 2.3 并发

#### 概述

**并发程序设计**将程序分成若干个可同时执行的模块，模块之间的关系分为无关和交互。

1. **无关**：进程执行与其他进程无关。并发进程的无关性是进程的执行与时间无关的充分条件。

2. **交互**：进程执行影响其他进程，**竞争**和**协作**是进程的两种基本交互方式。
   1. 竞争：一个进程占有资源，另一个等待，带来**死锁**和**饥饿**的问题；
   2. 协作：不同进程按一定的协调次序执行任务。
   3. 竞争的解决方法是**互斥**，协作的解决方法是**同步**。




#### 互斥

同一时刻仅允许有限进程访问的资源称为**临界资源**，访问临界资源的过程称为**临界区**。

**临界区互斥准则**：

1. **空闲让进**：临界区空闲时，允许进程进入；
2. **忙则等待**：临界区忙碌时，其他进程等待；
3. **有限等待**：进程等待时间有限；
4. **让权等待**：进程等待时挂起，不占用CPU资源。

**互斥的软件实现**：

1. 单标志：不符合空闲让进、有限等待、让权等待

   ```
   global bool turn = true;
   
   process P0 {
   	while (turn) ;
   	{临界区}
   	turn = true;
   }
   
   process P1 {
   	while (!turn) ;
   	{临界区}
   	turn = false;
   }
   ```

2. 双标志先检查：不符合忙则等待、让权等待

   ```
   global bool flag1 = true;
   global bool flag2 = true;
   
   process P1 {
   	while (flag2) ;
   	flag1 = true;
   	{临界区};
   	flag1 = false;
   }
   
   process P2 {
   	while (flag1) ;
   	flag2 = true;
   	{临界区};
   	flag2 = false;
   }
   ```

3. 双标志后检查：不符合空闲让进、有限等待、让权等待

   ```
   global bool flag1 = true;
   global bool flag2 = true;
   
   process P1 {
   	flag1 = true;
   	while (flag2) ;
   	{临界区};
   	flag1 = false;
   }
   
   process P2 {
   	flag2 = true;
   	while (flag1) ;
   	{临界区};
   	flag2 = false;
   }
   ```

4. Peterson算法：不符合让权等待

   ```
   global bool flag1 = false;
   global bool flag2 = false;
   global int turn = 1;
   
   process P1(){
   	flag1 = true;
   	turn = 2;
   	while(flag2&&turn==2);
   	{临界区};
   	flag1 = false;
   }
   
   process P2(){
   	flag2 = true;
   	turn = 1;
   	while(flag1&&turn==1)
   	{临界区};
   	flag2 = false;
   }
   ```



**互斥的硬件实现**：

1. 关中断，无法切换进程；

2. TestAndSet，TS：不符合让权等待

   ```
   // TS函数仅为逻辑，实际由电路实现，不会被中断
   bool TS(bool &x){
     if(x){
       x = false;
       return true;
     } else return false;
   }
   
   bool s = true;
   
   process P(){
     while(!TS(s)); //上锁
     {临界区};
     s = true;      //开锁
   }
   ```

3. Swap：

   ```
   // SWAP由硬件实现，不会被中断
   bool lock = false;
   
   Process Pi(){
   	bool key = true;
   	do{
   		SWAP(key, lock);
   	}while(key);		//上锁
   	{临界区};
   	SWAP{key, lock};//开锁
   }
   ```



#### 同步

**信号量 semaphore**：

1. 数据结构sem包含整型值和等待队列。
2. 进程只允许用PV操作访问信号量sem：

   - P：sem减1，若结果小于0，则调用P(sem)的进程挂起到等待队列；
   - V：sem加1，若结果不大于0，则将一个等待队列的进程转为就绪态。



**管程**和**条件变量**：

1. 由共享资源和访问共享资源的过程所组成的软件模块称为**管程**。
2. 管程中控制进程访问的变量称为**条件变量**，进程对条件变量仅支持wait/signal操作：
   1. wait：阻塞调用进程并释放管程，直到该条件变量执行signal；
   2. signal：释放被阻塞的其他进程，若无，信号不被保存。



经典同步问题：

1. 生产者和消费者：
   1. 容量为n的缓冲区，只能互斥访问；
   2. 缓冲区未满时，生产者可以生产产品放入；
   3. 缓冲区非空时，消费者可以消费其中产品。
2. 读者和写者：
   1. 多个读者和写者共享一个文件；
   2. 允许多个读者同时读；
   3. 写时，不允许其他读者和写者访问。
3. 哲学家就餐：
   1. 一张圆桌，n个哲学家，每两个哲学家间1根筷子，共5根；
   2. 必须同时持有左右两根筷子才能就餐。



#### 死锁

一个进程集合中，每个进程都在等待其他进程，无法执行的现象称为**死锁**。

死锁的必要条件

1. **互斥**：系统中存在进程应互斥使用的临界资源
2. **占有和等待**：进程请求资源不得到满足而等待时，不释放已占有的资源

3. **不剥夺**：已被占有的资源只能被属主释放，不允许被其他进程剥夺

4. **循环等待**：存在循环等待链，每个进程都在链中等待下一个进程所持有的资源

死锁的处理策略包含**预防**、**避免**和**检测并解除**。

**死锁的预防**：导致资源利用率和吞吐率低

1. 破坏互斥：使资源可同时访问而不是互斥使用
2. 破坏占有和等待：静态分配
3. 破坏不剥夺：剥夺式调度

**死锁的避免**：**银行家算法**

1. 比较剩余资源和进程需求，分配资源给能满足需求的进程；
2. 该进程运行完毕并归还全部资源，剩余资源增加；
3. 重复上述步骤，如果能完成全部进程说明系统处于**安全状态**，执行的序列称为**安全序列**。

**死锁的检测和解除**：

检测：**资源分配图**，圆表示进程$P$，方框代表资源$R$。

1. 边$P_i\rightarrow R_j$表示进程$P_i$等待资源类$R_j$中的一个资源。
2. 边$R_j \rightarrow P_i$表示$R_j$类中的一个资源被进程$P_i$占用，从方框内的某个黑圆点出发指向进程。
3. 若进程的请求边和分配边能全部消去，消去后的进程节点称为孤立节点；
4. 若能使所有进程成为孤立结点，称该图是**可完全简化**的。
5. 资源分配图不可完全简化是死锁的充分条件。

解除的方法：

1. 结束进程：
   1. 结束所有进程。
   2. 撤销陷于死锁的所有进程。

   3. 逐个撤销陷于死锁的进程，回收其资源重新分派，直至死锁解除。

2. 资源：
   1. 剥夺死锁进程的资源，直至死锁解除。
   2. 可能随着某些未卷入死锁的进程执行，会释放足够解除死锁的资源。
3. 系统建立保存检查点、 回退及重启机制；根据检查点回退所有进程，直到解除死锁。
